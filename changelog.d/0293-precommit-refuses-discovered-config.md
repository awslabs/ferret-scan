### 🔒 Security

- A config file found in the working directory (`config.yaml`, `ferret.yaml`, `ferret.yml`, `.ferret-scan.yaml`, `.ferret-scan.yml`) is now refused in pre-commit mode, on `--file` and `--stdin`: nothing is scanned, the exit code is 1 and stderr names the file and both ways out. Pre-commit mode is `--pre-commit-mode` or any of `PRE_COMMIT`, `_PRE_COMMIT_RUNNING`, `PRE_COMMIT_HOOK`, `GIT_HOOK_TYPE`. Before, a config added by the commit under review could redefine the `precommit` profile as one check, and the hook then exited 0 with its only output (a stderr note) hidden by pre-commit, which prints a passing hook's output only with `verbose: true` ([#293](https://github.com/awslabs/ferret-scan/issues/293), THREAT_MODEL TM-13, now mitigated in both halves). The new `--allow-project-config` flag uses the file as before; it is command-line only, so no config key or environment variable can set it. A config from the user config directory, or named with `--config <path>`, is unaffected, and so is a run outside pre-commit mode.
  ⚠ A hook that relies on a project config file must add `--allow-project-config` (or `--config <path>`) to its `args`, or it now exits 1 with the error. The shipped `.pre-commit-hooks.yaml` does not carry the flag.
